# ilovechiikawa 專案計劃書

> 最後更新：2026-10-15　·　狀態：從 ilovetomica 擷取功能完成，待首次部署

## 1. 產品定位

**一句話**：給吉伊卡哇玩偶收藏者的管理工具，用 AI 拍照鑑定、標出仿冒疑點，並給出**可解釋**的行情估值。

**為什麼是這個題目**：玩偶的價值分歧點在出處（官方店／夾娃娃機／一番賞）、尺寸、吊牌與真假，
而且仿冒品多到「有沒有查證過」本身就是行情的一部分。這些都是圈外人看不出來的細節。

**刻意不做的事**：不做交易平台、不做社群、不擴到其他角色 IP。

## 2. 從 ilovetomica 擷取了什麼

| 沿用（幾乎不改） | 改寫成玩偶語彙 |
|---|---|
| 儲存驅動抽象（本機檔案 + Vercel Blob、ETag 樂觀鎖） | 品牌 → 出處（`channels.ts`），產地敏感度 → 仿冒敏感度 |
| 收藏庫 CRUD 與 API、局部更新（`pickProvided`） | 包裝形式 → 尺寸；盒況 → 吊牌狀態；車況 → 本體狀態 |
| 匯出／匯入、PWA、照片縮圖 | 車款人氣 → 角色人氣（明確欄位）＋造型主題（關鍵字） |
| 可解釋估值的乘數模型與比較的「價差來自哪裡」 | 新增「正版查證」維度與 AI 的仿冒疑點欄位 |
| AI 鑑定流程（structured output、寬容解析、prompt cache、示範模式） | 判讀順序改為：吊牌 → 產品線 → 角色 → 尺寸 → 仿冒疑點 → 狀態 |

刻意**沒有**帶過來的：舊資料欄位遷移（`migrate.ts`）——這是新專案，沒有舊資料要相容。

## 3. 估值模型

```
估值 = 產品線基準行情（S 尺寸）
     × 稀有度       (S 4.0 → D 0.8)
     × 尺寸         (BIG 3.8 → 吊飾 0.55)
     × 正版查證     (已查證 1.0 → 確認仿冒 0.05；未查證／疑似仿冒依出處的仿冒敏感度縮放)
     × 本體狀態     (全新 1.0 → 有損傷 0.15)
     × 吊牌狀態     (未拆袋 1.3 → 無吊牌 0.55)
     × 角色人氣     (小八、烏薩奇 1.3 → 其他角色 0.95)
     × 造型主題     (討伐 1.15 → 扭蛋 0.9)
     × 特別版       (依出處：ラストワン賞 2.5、聯名非賣品 2、抽選販售 1.8…)
     × 停售年資     (每滿 1 年 +5%，上限 +30%)
```

區間為中位數的 −25% / +35%。內部以新台幣計算，日本出處換算回 JPY，台灣授權商品直接以 TWD 顯示。

## 4. 待驗證項目

### 4.1 AI 辨識品質（最大的未知數）
請求內容（模型代號、圖片 block、structured output、fallback、prompt cache）已有測試攔截 fetch 驗證，
但**真實照片的判讀準確率沒有實測過**。

驗收方式：拿 20 隻自己的玩偶，每隻拍三張（正面全身／吊牌正反面／布標），用
`npm run verify:ai -- 正面.jpg 吊牌.jpg 布標.jpg` 跑一輪。

| 指標 | 目標 |
|---|---|
| 角色判對率 | ≥ 98% |
| 出處判對率（有拍到吊牌） | ≥ 90% |
| 尺寸落在相鄰一級內 | ≥ 85% |
| 已知仿冒品被標為疑似仿冒 | ≥ 70%（寧可多報） |
| 信心度校準 | 判錯的案例，信心度應普遍低於判對的案例 |

### 4.2 行情基準值
`series.ts` 與各項係數是估計值。上線後用 Mercari「売り切れ」與駿河屋買取價校正。

### 4.3 Vercel Blob
與 ilovetomica 相同的驗收清單：重新整理資料還在、`/settings` 顯示 Vercel Blob、
兩個分頁同時修改不互相覆蓋。

## 5. 路線圖

- **Phase 1（完成）**：領域模型、拍照鑑定、仿冒疑點、可解釋估值、收藏庫、統計、比較、備份、PWA
- **Phase 2 上線**：部署到 Vercel、真實 API 驗證（4.1）、存取控制（至少一層密碼）
- **Phase 3 體驗**：每隻多張照片（正面／吊牌／布標）、照片改存獨立 Blob、願望清單、
  一番賞整套進度追蹤（A–Z 賞與ラストワン賞收集狀態）
- **Phase 4 真實行情**：接入成交資料、價格趨勢、以實際成交回推校正係數

## 6. 部署程序

1. Vercel → Add New Project → 匯入 `papap35/ilovechiikawa`
2. 專案 → Storage → Create → Blob（**不能跳過**，會自動注入 `BLOB_READ_WRITE_TOKEN`）
3. 環境變數：`ANTHROPIC_API_KEY`（必要）、`CHIIKAWA_JPY_TWD`（選填）
4. 部署後打開 `/settings` 確認儲存位置顯示「Vercel Blob」
5. Functions 區域選 Tokyo (hnd1) 或 Singapore (sin1)

## 7. 風險

| 風險 | 對策 |
|---|---|
| AI 誤判真假 | AI 最多給「大致可信」；疑點逐條列出供人工比對；估值明確標示為參考值 |
| 行情與實際成交落差大 | 係數集中可調；Phase 4 用成交資料校正 |
| 角色 IP 與商標 | 僅作事實性描述；不使用任何官方圖像；聲明與原作者及授權商無關 |
| 公開網址無存取控制 | Phase 2 補上 |
